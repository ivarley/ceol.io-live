27;2;13~27;2;13~# 034 Session Person Changes
We need to clarify and regularize how people are associated with sessions and session instances, both in the model and the UI. 

First off, let's declare that session_person is a representation of ANY relationship between a person and a session (and could be created either implicitly or explicitly). There's an enum explaining the "seriousness" of the relationship, which can be any of "regular" (someone who comes often), "attendee" (someone who comes, and presumably lives locally, but isn't there often enough to be called a "regular") and "visitor" (someone who lives elsewhere but comes occasionally).

The first method of creating the association is by the user directly; if you visit a session home page and you're not already associated, you see something that says "Do you attend this session? _Yes, Add Me_"

Change 1: Let's make a modal here (before directly adding you) that says: "Are you a local, or just visiting?". Then if they say "local", ask a second question: "Do you attend regularly, or once in a while?". The answers to these questions determine which of the three statuses you get.

Change 2: Once you've joined, when you visit the session home page, you see a badge on the right that (today) says "Member" or "Admin". Change this to say one of "Regular", "Attendee", "Visitor" or "Admin", and make it so that clicking it brings up a modal where you can change between "Regular", "Attendee" and "Visitor" (you can't choose "Admin" because that has to be set by a system admin, at least for now) with a "Save" button.

On the user profile in the "My Sessions" tab, you can currently switch between "All Sessions" and "Regular Sessions".
 
Change 3: Change this to be a toggle between "Where I'm: [Attendee] / [Regular] / [Visitor] / [Admin]" and it filters the list. It starts unfilitered and shows all, and if you click a select option again it unselects and goes back to all". Change the title of this from "My Sessions" to "Sessions". Instead of the "Add another session I've been to", use the standard "+" button on the top right of the results. Chang ethe "Add me ..." modal to match the options (Regular / Attendee / Visitor) and don't show any results until you search by name (so it's a search rather than a filter). 

The second path for user / session relationship is by someone else in the context of a particular session, typically an admin. The user can either be directly added from the Session's "People" tab (where there's both an "add" and "create person" option). The same general thing can also be done within the context of a session instance, though in that case the real estate of the current design makes it very difficult to use, with constant scrolling.

Change 4: Create a single flow (full screen on mobile, right pane on desktop) where you can see and filter who is already associated with the session (or session instance), and the same "Type to filter" also initiated a "type to add", in a tierd way that first looks among people who could be but aren't yet in the list, then allows you to add a new person if needed. Note that this is different for "session person" and "session instance person":
 - For session person, you start seeing all the session people, you type to filter the list, and if nobody comes up, you click add, you type to search across all people in the system, and if they don't come up that way you can enter a new person.
 - For session instance person, you start looking at a list of everyone associated with (checked in to) this instance, which again you can filter if you want. This view, however, also now starts to include some "dimmed" results which equate to people who are already associated with this session (session_person) but not yet this instance. This would be the common check-in flow.
